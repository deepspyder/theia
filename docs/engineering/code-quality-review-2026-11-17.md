# 兼容修复代码规范审查

日期：2026-11-17。范围为本轮全部未提交兼容适配、构建工具和相关调用链，并检查全部 147 个 Kotlin 文件的分包与依赖方向。本记录不是对历史全库逐行审计或“没有任何 bug”的承诺。

## 已修正

### 构建校验不能依赖 assert

`tools/verify_windowed_spirv.py` 原来使用 Python `assert` 验证模块数量、字段类型、偏移和绑定合同。在优化模式下，空目录也会输出“0 compiled shaders ... verified”并成功退出，已用 `python -O` 实际复现。

现已改为不可被优化移除的显式条件检查与 `ValueError`，CLI 统一返回失败状态。补齐短文件头、截断操作数和缺失类型的错误信息；输出报告自动建立父目录。新反例测试覆盖空集合、短头部、错误字段偏移、错误整数类型、动态推送索引、畸形指令及固定/移动绑定错误，并在普通模式和 `-O` 下都通过。

### 构建适配与诊断代码分离

较长的 C++ 诊断逻辑不再嵌入 CMake 字符串，分别移到 `VulkanPreflight.cpp.in`、`VulkanPipelineContext.cpp.in`。CMake 只负责读取、追踪文件依赖和严格锚点替换；模板改变能触发重新配置，继续保持共享 Windows 源码不变。

### 固定计算移出循环

窗口绑定的移动掩码在每次内核调度中只计算一次，不再在每个分段的每个绑定中重复扫描 Rule 表。边界保护和比较条件保持。

### 统一格式与构建顺序

新增项目 `.clang-format`，统一四空格、120 列、左对齐指针/引用及保留 include 顺序，并格式化本轮新增的 C++ 代码与模板。没有全库格式化历史文件。显式同时请求资源同步、着色器编译和打包时，ABI 校验安排在同步与编译后，普通打包仍只执行验证，不新增自动编译所有着色器的启动成本。

## 资源和边界审查

复核了管线创建失败的半成品句柄清理、描述符池 RAII、临时缓冲所有者、同步提交后的资源复用、取消后会话关闭、分段对齐、尾部线程保护和固定表起点检查。未发现本轮改动中需要新增整图复制或清理原片的路径。固定掩码收敛不改变照片算法、材料数据或位深。
