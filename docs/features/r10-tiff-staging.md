# R10 TIFF16 压缩暂存优化

2026-11-20。无损 TIFF16 把逐块生成的 RGB 数据直接送入 Deflate，在写出 TIFF 头前通过文件描述符取得压缩条带的长度。压缩中只保留这一个已经解除文件名链接的临时文件，结束或进程退出时由系统回收。压缩与未压缩输出共用 TIFF 头和 RGB16 采样逻辑。每次读入最多 32 行，并按图宽进一步限制块大小。

API 37 x86_64 模拟器上的专业输出专项生成 32 个文件，包括四个色域下的正常与调色导出。八组 TIFF 压缩输出解压后与未压缩输出逐样本一致。专项检查压缩时暂存文件不可按路径打开、低空间拒绝、压缩中取消以及目标文件写入失败，验证了失败后文件描述符释放。

用 Nikon Z6II 的 `DSC_5099.NEF` 导出 6064×4040 TIFF16。电脑使用独立 TIFF 条带读取和 zlib 解压比对。压缩和未压缩 TIFF 以及单独生成的参考图具有相同的 146,991,360 字节 RGB 数据。两份实际导出的 ICC、EXIF 和 TIFF 其余头字段一致。Deflate 导出文件为 144,391,935 字节，该次命中渲染缓存，从发起导出到相册保存耗时 4.878 秒。模拟器全尺寸回归第一次触发 JPEG 的低空间保护，备份旧测试产物腾出空间后，七项全尺寸输出通过。

应用层 48 个导出用例覆盖 PNG、JPEG、WebP、DNG 四种来源，及裁切、旋转、317px 自定义长边和配置冻结。ProPhoto RGB 的 317px Deflate 重试通过完整像素比对，并验证重复提交和源变更保护。

Debug、AndroidTest、Release、Lint 和 15 项工具测试通过。签名和 16 KiB 对齐通过。执行记录位于 `.tmp/r10-tiff-strips/`。成片后期与文件编码迁移继续作为 R10 的后续工作。
