# R02 自定导出尺寸、命名与配方管理

日期：2026-11-18。承接 [2.4.2 开发清单](../upstream-2.4.2-android-roadmap.md) R02；本批基线 `a59ff5c`。保持应用名、ID、JNI、原生库、材料和旧编辑参数。

## 交付行为

- 分辨率菜单保留 2048 / 2560 / 3840 / 原始，增加“自定义尺寸”。支持最终成片长边/短边 1–65535 整数像素，以及 0.01–200 MP。无效或非有限值不能提交；对话框取消不改变当前设置。
- 自定义尺寸以原图完整渲染后的成片为基准，包含 EXIF、裁剪、旋转和片边，再按面积覆盖缩小；保持宽高比、按最近整数取像素边界、每边至少1像素，不放大。MP 目标因整数取整会有一个像素级的面积误差。
- 四档旧尺寸继续在解码阶段限长边；不重解释旧配方，也不改它们的输出。自定义与旧快速尺寸在颗粒采样/光晕缩小等方面不承诺逐像素相同；自定义输出的参照是完整原尺寸成片，绝不用预览冒充原图。
- 命名默认为原有 `Theia_时间戳`。自定义可选择原名（移除最后一个扩展名）、胶片显示名、相纸显示名、导出当天日期，点选添加/移除、箭头排序、选择下划线/短横线/空格，并预览文件名。日期不是拍摄 EXIF 日期，不会因关闭拍摄信息而偷偷读取拍摄时间。
- 文件名规范化并清除路径分隔符、控制/方向字符与非法字符，以UTF-8字节限制长度而不截断代理对。重复名称增加 ` (1)`、` (2)` 等；不覆盖已有成片。
- 导出配方保存全部格式/尺寸/命名/色彩/质量/元数据选项；支持重命名和删除，删除有确认。同名保存明确替换，重命名不能占用其他配方名；空名称、过长名称和存储错误有提示，失败不关闭对话框。
- 自定义尺寸同样用于软打样；显示仍受3400px预览上限约束，不发布照片。DI TIFF 保持独立的旧中间文件工具语义，不套用成片尺寸/命名组合。

## 代码职责与兼容

| 层 | 责任 |
| --- | --- |
| `core.model/ExportSize.kt`、`ExportNaming.kt` | 无界面尺寸/命名值与版本化JSON；中性默认 |
| `core.model/ExportOptions.kt`、`ExportFrameRequest.kt` | 冻结提交；IPC schema3，保留schema1/2读取；拒绝畸形新选项 |
| `data/export/SizedRgba16Source.kt` | U16面积积分、行级缓存与取消，只有O(行宽)工作缓冲；不缓存整张缩放图 |
| `data/export/PhotoExportPipeline.kt` | 单张/批量共用最终缩放和编码；缓存保留原始完整渲染，按请求再次缩放 |
| `data/cache/ExportRenderCache.kt` | 自定义请求按实际原始渲染尺寸形成缓存身份；名称不影响像素缓存 |
| `data/local/RecipeStore.kt` | 保持`recipes.json`旧数组格式；AtomicFile写入、未知字段合并、损坏/未来版本拒绝覆盖、空列表不复活默认配方 |
| `data/export/ExportPublisher.kt` | MediaStore及应用目录去重、串行命名预留、失败/取消清理；本地发布不使用REPLACE_EXISTING |
| `feature/export` | 尺寸、命名、配方管理独立组件，沿用现有主题/选择行；新文案资源化 |
| `feature/editor/EditorViewModel.kt` | 提交冻结、配方异步IO与状态反馈、现有预览/导出协调 |

未增加Gradle依赖、线程池、后台服务或网络调用；未切换兄弟引擎。自定义尺寸需要原尺寸显影，首次成本和峰值仍受F03限制；行级缩放不等于整个显影已低内存化。

## 性能口径与剩余项

输出矩阵每项记录端到端`elapsed_ms`。同一原始渲染可供不同自定义尺寸/容器复用；第一次包含原图读取/显影，后续可能命中成片缓存，不能直接解释为编码器或手机加速。测试关闭上述随机效果，不能与先前CineStill正式效果耗时直接比较。

本批完成R02，不等于F15全部专业输出能力或F16全部进程续跑验收完成。ARM驱动、真实云端、满盘/后台长期负载继续按原计划；更高像素首次显影峰值、专业色域/HEIF及HDR分别由F03/R08/R22推进。

新增待排能力：本轮DI TIFF成片回导失败，普通非DNG TIFF的输入解码路径尚未接通；输出TIFF16并不代表支持将其作为输入再读回。此项保留为后续输入兼容专项，本批没有改输入解码器或把它声明为已修复。
