# R08 专业 SDR 输出、HEIF 与无损 TIFF

日期：2026-11-19。基线 `8d67b1e`。本批延续现有导出页与独立 render host，不修改兄弟桌面 checkout。

## 输出合同

JPEG、PNG、TIFF 可以选择 sRGB、Display P3、Adobe RGB (1998)、ProPhoto RGB。新输出空间执行真实像素转换，之后嵌入相同空间的 ICC；不是只写配置文件。为保持已有编辑和默认输出，继续使用已有 SDR 成片工作路径：普通输出在 sRGB 调色，既有 P3 TIFF 仍走其 P3 路径；新增空间在成片裁切、尺寸限制和调色后转换。新选项不会恢复先前工作空间已裁掉的颜色，也不作为 HDR 或全链宽色域宣传。实际屏幕打样/100%细节继续属于 R09。

TIFF 维持 RGB16；Deflate 是默认关闭的独立无损选项，不加预测器、不改像素。使用两个私有暂存文件，按有界分块压缩已有 TIFF 像素条带，完整保留 ICC、EXIF/GPS、方向及样本。预先检查暂存空间，失败/取消清除暂存，输出继续走原子发布。

HEIF 使用 AndroidX HeifWriter 1.1.0，扩展名 `.heic`、MIME `image/heic`，仅 SDR sRGB 8 bit。API28 以下禁用；支持的版本也先实际编码并读回32×32样本，缓存本进程探测结果。无能力时界面明确不可用；单张和批量预检拒绝。支持探测失败隔离，包括缓存 IO、codec、内存不足和链接错误，不让可选功能阻断启动。没有重命名 JPEG 的回退。App minSdk 仍为26；API28实现隔离，manifest 只为可选库覆盖其 minSdk。当前没有API26系统镜像，低版本运行烟测仍待，Lint API检查通过。

HEIF 的 AndroidX drain 没有同步取消接口；取消在编码返回后、复制和发布前响应，drain超时30秒。完整Bitmap和首次显影峰值仍存在，不宣传内存优化。EXIF通过容器编码器原生写入；不依赖不支持HEIF写回的ExifInterface。

## 兼容与修复

配方升到version2，读取旧配方时将旧版JPEG/PNG遗留P3值按旧实际行为归一为sRGB；未知JSON字段仍保留，原子存储与坏文件保护保持。冻结请求升schema4，读取schema1—3按旧非TIFF语义恢复，新压缩字段缺省false。提交后切换UI颜色/压缩不改变正在执行的请求。渲染身份加入output-color版本，避免复用语义不一致的旧缓存。

JPEG采用分段APP2 ICC。独立Pillow读取首先发现系统编码器本身已写sRGB配置，额外插入目标配置会形成冲突。现对有显式目标ICC的输出解析原始标记段、仅移除原ICC_PROFILE APP2，保留其他段/压缩像素；默认sRGB保留原路径。覆盖单字节写入、65519字节分界、多段配置重组/替换及取消。PNG宽色域写iCCP，sRGB保持既有sRGB块。P3沿用已有ICC；新矩阵/TRC配置使用D50 PCS与4096采样曲线。

- NumPy独立标准原色矩阵、Bradford和传递函数对照共808,008个U16通道样本。sRGB差0、P3/ProPhoto最大2，Adobe最大16（P99为5）。Android平台标准色坐标的常量舍入与独立双精度参考存在小差异；完整24.5MP Adobe输出最大19/65535，平均约0.566码值。验证阈值20/65535，保留实际误差，不写成逐位相同。LittleCMS读回相对独立色管参考的P99误差至多1个8位码值；8位ProPhoto往返因量化本身P99损失4—5，不能作为16位或无损输出宣传。
- 实际应用内PNG、EXIF6 JPEG、WebP片边日期、DNG输入，四空间×三格式共48份输出。调色、成片裁切、旋转和317px长边限制后逐完整像素与参考核对；PNG最大差1码值（默认为0），TIFF默认/P3为0，新转换空间在上述精度界限内。JPEG做完整解码和误差统计，有损结果不要求逐位相同。冻结参数、真实虚拟副本/同名批量、软打样尺寸和取消发布路径通过。

- 模拟器实际HEIF探测可用，257×131、1×1、1025×769编码/读回、像素和EXIF/GPS/方向、取消及暂存空间保护通过。界面另外故障注入不可用能力，覆盖已保存HEIF选择的明确错误与单张/批量不开始发布；不将此写成实际不支持设备的验收。
