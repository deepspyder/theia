# R04 灰点白平衡吸管

日期：2026-11-18。基线 `23fcbfd`，对应 [2.4.2 清单 R04](../upstream-2.4.2-android-roadmap.md)。本批扩展现有拍摄/调色面板，保留共享引擎、胶片材料、默认解码数学和原始输出尺寸。

## 两个采样阶段

- **RAW 灰点吸管**打开独立的、已应用 EXIF 方向的解码源图，位于镜头校正/裁剪/旋转/胶片处理之前。界面明确标记阶段，不把当前裁剪成片触点反推到传感器，也不从相机 JPEG 或截图取色。最长边 1024 的 float ProPhoto 预览仅为测量会话驻留；实际导出仍按原参数/指定尺寸重新解码。
- **成片灰点吸管**显示当前引擎输出在应用调色之前的状态，包含已有构图/旋转/片边。从对应 RGBA16 缓冲读取通道，保留 U16 精度；显示位图经过既有色彩显示变换，只作为触点参照。sRGB/P3 采样均在调色实际作用的编码空间中求解。
- 触点按 ContentScale.Fit 精确换算，留白区域拒绝取样。以 7×7 邻域（边缘截断）平均有效像素，超过一半不合格时拒绝；过暗、过曝、透明和非有限值不能生成可应用候选。成片暖冷/tint 超出既有 [-1,1] 范围时限幅并显示提示；RAW 超出 2000…50000K 或 tint ±150 时拒绝。
- 只在明确“应用白平衡”时更新参数并提交单独的历史步骤。返回/取消、准备期间取消、失败或源/编辑变化均不写编辑。提供中心采样按钮供不便精确点按时操作。全屏弹窗使用现有 Material 3、圆角、字体与琥珀配色。

## 底层与兼容

LibRaw 在既有 convert_to_rgb_loop 调用前仅复制实际 output-from-camera 矩阵，随解码结果记录实际 pre_mul 和通道数；基类运算原样执行。新 JNI 只负责相机标定与有界采样预览，既有 JNI 签名/结果构造器保持。RGB 经逆输出矩阵、去除实际 WB 乘数、逆相机 XYZ 矩阵和 Robertson 逆表转换为 Kelvin/tint；不通过重复完整解码迭代求色温。成片使用现有 `.18` 暖冷、`.12` tint 增益的闭式解。

新增 `camera_wb_temperature_as_shot` 与 `camera_wb_tint_as_shot`，缺省均 false；旧 custom=false 原生拍摄白平衡，旧 custom=true 两轴显式。两轴同时沿用拍摄值时直接使用原生拍摄 WB；单轴模式由当前相机 cam_mul 和 cam_xyz 反推拍摄值，不能把另一张照片的标定复制过来。无法换算时禁用单轴入口，完整旧自定义值继续保留既有不支持矩阵时的拍摄值回退。日光/多云/阴影/钨丝灯/荧光灯/闪光灯预设与恢复拍摄 WB 共用解码链路。

分组复制/命名预设/sidecar/虚拟副本、交互解码、单张与批量导出均携带新轴标志。R03 历史摘要规范化时删除为 false 的新默认键，避免打开旧记录后误判摘要损坏；true 值仍参与摘要。无数据库 schema 升级。

RAW 会话创建临时的精确源字节快照，以持有的文件描述符读取；应用前重新验证本地文件/MediaStore 原始字节摘要，并核对照片代次和冻结编辑。任意 provider 的云端流按原有 ExportSourceSnapshot 合同只拉取一次，以不可变会话快照为准；不承诺再次下载云端源。成片取样冻结当前引擎帧与编辑身份，不另行读取源文件。取消/关闭释放描述符和测量数组，不建立永久原图副本或解码缓存。位图放弃引用后由 Android 回收，避免仍被 Compose 绘制时 recycle。

## 验证记录

验证环境为 Android17/API37 x86_64 模拟器。宿主为相同源码 Debug DEX 加当前 Release 原生库；未在 ARM 手机或厂商驱动运行，不声称与 Release DEX 相同。最终汇总 `.tmp/r04-neutral/verification.json`：25 组、235 条执行记录，完整应用总入口 207/207；4 配置 28 张原生截图。此处统计执行行，专项与总入口有重叠，不是235个互不重复产品功能。

保留的首轮失败与修正：

- 数学测试将一个 XYZ 的 Z 为负的极端合成光源误当作可采样灰点；产品正确拒绝，夹具改为明确验证拒绝。
- RAW 去抖/重新解码的等待期未纳入吸管入口可用条件，可能出现按钮看似可用、点击无动作。现共用既有可观察 previewWorkRunning，覆盖去抖、解码、渲染与调色。
- 旧 DNG 自定义 WB 在不支持矩阵时原来回退拍摄值，新 resolve 最初抛错；完整应用回归明确检出。保留旧回退合同，单轴无法换算仍明确拒绝。
- 首轮截图显示导航手势条遮挡底部操作按钮，按现有全屏曲线编辑器模式预留导航区域；修正后同四配置重新截图，独立复核的 verdict 为 ship，原 P1 评分 resolved；该 verdict pass 只覆盖这一修复。
- 高效率 NEF 审计使用历史整图 renderForExport，R03/R04 同样触发严格缓冲绑定上限。用例改用产品当前 renderExportOnce，保留独立 RAW 像素参考、真实解码中取消、截断拒绝、6064×4040 与 TIFF16 断言。
- 原尺寸夹具最初写错 DSC_5099 相机尺寸；现以该原片 IFD 的 6064×4040 与完整原生解码尺寸交叉核对，未降低导出尺寸。

## 最终功能、像素和性能证据

1. **独立数学**：105 组成片增益反解、17 组有效 Robertson/相机逆变换，另验证物理不可达光源、非有限值、限幅、Fit 留白/边缘邻域、四种轴模式、旧预设与 R03 旧摘要。没有用被测方法的返回值当作唯一预期。
2. **两份真实 Nikon NEF**：从 float 阶段取样后重新解码，相同点最大绝对 log(R/G)、log(B/G) 分别为 0.011479、0.008169（最大通道比例差约1.15%、0.82%），均小于0.04阈值。两图×四种轴组合的导出解码接线结果与直接设置相机乘数后引擎输出的完整 U16 阵列逐值相同。
3. **旧版对照**：先安装 R03 `23fcbfd` 的宿主记录10份旧 RAW，再安装本批宿主；默认/自定义 WB 预览、相机矩阵/乘数、尺寸和有界导出 float 样本全部摘要相同。199份运行资产（其中193份 engine 资产）逐字节不变；仅两ABI的 libspektralab.so 因新增 JNI/标定捕获改变，另外四份原生库保持，不能声称所有SO二进制不变。
4. **实际交互**：JPEG EXIF6、PNG、WebP，源构图叠加裁剪/四分之一旋转/3.5°旋转，真实触点注入与中心按钮，实际取消/应用、undo/redo/reopen及九次384档三容器发布通过。RAW预设、两轴开关、测量应用、独立混合轴导出、虚拟副本测量与两个不同批量PNG通过；实际新进程恢复已选WB、混合轴redo分支并重新解码验证。
5. **原始尺寸**：DSC_5099 的原生完整尺寸与 NEF IFD均为6064×4040，吸管应用后实际JPEG/PNG/TIFF原尺寸发布通过，PNG头尺寸与完整原生解码交叉核对。另 HE★ Z5II 独立官方解码像素参考、20次回调后真实解码中取消、截断拒绝、完整6064×4040 TIFF16及编辑器导入通过。
6. **边界/布局**：保留低8位的U16/P3样本精确校验、全黑/过曝/透明拒绝、候选取消、编辑过期、RAW文件字节变化、准备期间关闭通过。手机1080×2400@420、1.3倍字体、横屏2400×1080@420、平板1600×2560@240实拍，包含加载/缺源失败/按钮禁用和系统Back；测试后恢复原始设置。界面复核只把底部导航遮挡判为已解决，不扩大为新一轮全表面审计。

## 范围限制

灰点采样只校正该阶段的白平衡；后续胶片色彩、其他调色和已限幅成片不保证最终显示绝对中性。RAW 缩图与去马赛克/量化使二次解码仍可能存在小残差，真实样片与阈值在测量记录中给出。饱和颜色超出支持范围时提示换点，成片范围内不会识别用户选到的物体是否本应是灰色。

小米15Ultra 原失败 DNG 仍未提供，Xiaomi/vivo GPU/手机性能不在本轮验收。普通非DNG TIFF 回导、HDR/专业色域与原尺寸瓦片仍待对应工作包。R03 同步历史提交 P95 的既有性能限制仍保留，不能从本轮模拟器测量推断真机耗时。

设计文档复核：本批延续既有 DESIGN.md 的材质、字体、圆角和触控规范，无新视觉系统或全局token；文档复核保持该文件不变。R04功能合同由本报告记录，后续顺序为R05设置、缓存与诊断入口。
