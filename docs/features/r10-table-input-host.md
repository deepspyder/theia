# R10-C1 灯台已编辑照片使用独立进程渲染

日期：2026-11-19。基线R10-B `2536738`。本批只迁移灯台中已编辑照片的源解码/渲染，保留原图外观的直接解码、TableExportSession事务、拼版/材质/文字/透明和PNG/JPEG发布路径。同一 R10 内剩余的多源任务恢复、拼版与编码迁移已暂停。

`TablePhotoRenderer`接收冻结TableExportInput，保持原有裁切补偿长边计算和4096px上限，复用PhotoExportPipeline的源快照、实际源SHA、冻结随机实现、缓存、宿主与成片后期/裁切量化。内部源渲染不创建用户导出成功记录。主ViewModel只保留输入顺序、预览交接和用户状态；同一来源多处摆放继续共用一份暂存图。实际源与准备阶段SHA不符时拒绝暂存，TableExportSession仍会复核编辑revision、原图内容和发布状态。

灯台提交时持有RenderHostLease，缓存未命中前释放编辑引擎；完成或失败后先等待宿主释放设备，再恢复原编辑会话，避免两个进程同时保留Vulkan设备。取消由共享host checker/abort合同传递，移除只适用于旧本地灯台渲染的tableNativeRendering标记。进度仍位于原有来源序号区间，细分单张渲染百分比，不改变输出页布局或文案。

共享PhotoExportPipeline新增可选validateRendered，默认不改变单张/批量/DI路径。灯台在成片裁切前验证原始渲染栅格的尺寸/容量，防止4097px的缓存源在裁成小图后绕过既有4096px限制；不降低用户输出尺寸或放宽原有限制。原图外观和未编辑RAW拒绝规则保持。

新增专项以PNG、EXIF6 JPEG和DNG建立独立的完整画面调色→裁切参考；核对宿主输入、确定性缓存相同、渲染阶段取消、超限缓存裁前拒绝及不产生内部导出回执。首轮红测来自测试夹具误用1%成片裁切，被既有2%下限正确拒绝，生产参数规则未改；修正合法夹具后继续执行。回归包含混合原图/编辑外观、虚拟副本、几何/Decode曲线、实际NEF项目、源变化/过期编辑/取消和PNG/JPEG事务。


PNG、EXIF 方向 6 的 JPEG 和 DNG 共 255,353 个像素，与独立的完整画面调色再裁切参考逐像素一致。夹具让 DNG 使用 `.jpg` 条目名，让 PNG 和 JPEG 使用 `.nef` 条目名。导出按来源探测取得的文件名选择解码器。冷渲染、确定性缓存命中、渲染中取消、4097px 裁前拒绝及内部渲染回执检查均通过。

早期实现的六组八条专项覆盖虚拟副本几何、Decode 曲线、拼版和事务。来源文件名修正后，九处混合外观、真实 Z6II NEF 虚拟副本、57 次实际单张导出与 DI 链路的定点回归通过。NEF 生成 1600×1101 PNG，与独立绘制参考的整图最大通道差为 0。从提交灯台项目到返回结果，最终一轮缓存命中耗时 2.938 秒，早期同案例的一次测量为 10.554 秒。两次均在 API 37 x86_64 模拟器进行。

最终界面专项通过。实际发布了 1600×1600 透明 PNG 和 A4 JPEG，验证过期编辑拒绝、显式应用最新编辑、取消后无残留文件，以及回到编辑器继续编辑和撤销。一次早期界面尝试收到空截图，另一轮被模拟器的系统界面无响应弹窗遮挡。测试增加了保持亮屏、有界截图重试和诊断，处理弹窗后重跑通过，整轮耗时 112.27 秒。

Debug、AndroidTest、Release、Lint 和包边界检查通过。发布包 58,777,781 字节，SHA-256 为 `d22a453b15a063b2bccea086308acfe86d9f3d82614c951639aae924ec1eeaa4`，原证书 v1/v2/v3 签名和 16 KiB 对齐通过。测试记录位于 `.tmp/libraw-upgrade/` 下的 `r10-c-table-final`、`r10-c-source-name`、`r10-c-regression` 和 `r10-c-ui-final`。本次设备验收范围为 API 37 x86_64 模拟器。
