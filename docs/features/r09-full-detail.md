# R09 原尺寸细节与文件色彩打样

日期：2026-11-19。基线`01a3e38`。本批扩展现有暗房，不改桌面checkout，不改正式导出像素/尺寸/位深。

## 合同与实现

导出页新增“原尺寸细节 · 100%”。先冻结源、编辑、随机实现及所选文件空间，经既有源快照/独立render host/无损成片缓存生成真实全尺寸成片。细节忽略导出页自定义缩小限额，显示包含胶片片边、日期及两级裁切后的完整画面；不是放大小预览。100%定义为一个成片像素对应一个物理屏幕像素，拖动与双指缩放按屏幕像素计算，不受dp密度或预览尺寸影响。100/200/400%快捷控制与当前比例明确显示。

完整成片保存为取消时可回收的匿名/unlinked文件描述符，完整U16保留，查看不发布相册文件，也不生成导出成功凭据；与正式导出共用源身份和宿主，但以recordReceipt=false隔离只读查看任务。内存只驻留当前可见512px瓦片，每会话持有瓦片预算64MiB；使用RGBA_F16显示位图和明确的sRGB/P3标签，避免大图整帧Bitmap和错误ICC解释。读一整行的临时数组有界于完整宽度；当前缓存持有量不是整个进程/驱动/暂时GPU上传或等待GC旧帧的总内存上限。首次完整显影峰值未解决，仍属R10预算工作。

可见矩形、比例、屏幕尺寸、显示空间和session身份一起决定帧。32ms合并连续手势，旧job取消并检查generation，过期帧不能覆盖新请求。切图/改变编辑/关闭/离开前台/低内存关闭视图并释放描述符；配置变化重新计算可见瓦片。释放显示Bitmap的引用而不立即recycle，避免Compose尚在绘制旧帧时访问已回收像素。

软打样改为复用实际冻结文件输出链路：先完成调色、裁切、选定尺寸与文件空间转换，再缩小到至多3400px，最后转换到显示空间；JPEG/PNG/HEIF在文件空间先按实际8位量化，TIFF保留16位。支持真实文件sRGB/P3/Adobe/ProPhoto，保留原有交互预览raw结果，打样帧独立显示；修改编辑后正常交互重新显影。打样是文件像素的颜色预览，不模拟JPEG/HEIF有损编码，不宣称HDR、打印机/纸张ICC或超出旧SDR工作域的颜色恢复。实际屏幕能力只控制P3/sRGB显示路径；硬件验收单列。

## 测试与限制

首轮独立覆盖113,520个屏幕到成片坐标点，边界/奇数/超宽/缩放锚点，无重复/漏瓦片。四个文件空间、两显示空间、中性/调色暗角、多个视口，对照完整TIFF16后精确F16传输，56,696,832通道样本逐位一致；缓存重用、取消、空间不足和FD回收通过。50MP（8192×6144）和65535×9测试通过，完整U16临时存储、边界瓦片与64MiB持有预算明确验证；这两种是生成的像素夹具，不冒充真实相机RAW。

真实照片和DSC_5099.NEF实际独立原尺寸渲染，与所有可见F16瓦片逐样本对照；相同参数无缩小/不发布/编辑保留、后期裁切暗角、文件/显示颜色、快速30次请求/最终比例、关闭后拒绝读、取消及后台内存回收通过。最终四配置20张原生真实照片截图全部通过独立fresh五节ship复核；220条执行记录（含207总入口及专项重叠）、总入口207/207，导出恢复、宿主死亡/重启、实际快捷操作及批量通过。追加只读查看没有新增导出凭据的真实目录检查通过。汇总见.tmp/r09-detail/verification.json。

首轮Lint的HalfFloat规则把ByteBuffer.putShort的链式返回误判为半精度数值扩宽。没有替换系统Half数学或屏蔽全局规则：仅对putHalfBits原始位运输两行辅助函数局部说明并抑制该假阳性，实际TIFF→F16全样本验证保留。旧审计原先用lastResult判断打样，现改为检查真正显示的rendered尺寸/身份/F16标签；旧interactive raw帧继续独立，不把已调色打样再调色。
